# v0.1.0 コードベース再整理

実装状況一覧ではなく、v0.1.0 までに完了させる有限な再整理の計画と、その実施記録。
機能追加、仕様拡張、`docs/issues.md` の未完了項目は対象外とし、挙動維持を原則とした。

## 評価方式と再現コマンド

恣意的な総合点は作らず、同じコマンドで継続測定する。

```sh
git rev-parse --short HEAD
rg --files crates -g '*.rs' | wc -l
rg --files crates -g '*.rs' | xargs wc -l
find crates -name '*.rs' | xargs wc -l | awk '$2!="total" && $1>=1500 {print}'
cargo test --workspace --locked --no-fail-fast
cargo build --workspace --all-targets --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo check --workspace --all-targets --locked   # 最低要求バージョンで
```

LOC は trend proxy でありテストカバレッジではない。テストコードとコメントを
分離していないため、絶対的な品質点数として解釈しない。

## やったこと

### 1. 整形 (`24729cd`)

`cargo fmt --all` を単独コミットで通した。以降の分割コミットの diff を
「動かした行」だけに保つため、整形は必ず先に分けて入れる。

### 2. clippy と dead code (`2dba952`)

18 件を `#[allow]` を使わずに解消した。

読まれていないものは削除した。`Language::injections_query`、
`BackendClient::cancel`、`Theme` の 3 フィールド、`EditorLayoutInfo::gutter_width`。
protocol の `ClientMessage::Cancel` 自体はバックエンドが処理しているので残している。

引数が多すぎる 2 件は引数をまとめて直した。`syntax.rs` の `needless_range_loop`
だけは clippy の提案をそのまま当てると、末尾の連続区間を確定させる番兵の 1 周が
落ちて末尾のハイライトが出なくなるため、同じ反復になるよう自分で書き換えた。

### 3. 設計文書をコードへ畳む (`32daf98`)

`ARCHITECTURE.md` と `STATUS.md` を削除した。コードと別の場所で保守される設計文書は
実装が動いても追随せず、実際に session の保存先の記述が古くなっていた。

消すと根拠が失われるものは、それを守るべきモジュールの doc コメントへ移した。

| 移した内容 | 移し先 |
|---|---|
| 正本と複製、`base_version` の突き合わせ、`ApplyEdits` を直列に送る制約 | `nebula-backend/src/buffers.rs` |
| 排他をバックエンドの bind に任せる理由、古いビルドの検知 | `nebula/src/ipc_client.rs` |
| 最初のフレームより前に置いてよいものの境界 | `nebula/src/main.rs` |
| 外部ツールを CLI として叩く理由 | `nebula-backend/src/tools.rs` |
| ストリーミング結果の返し方 | `nebula-protocol/src/lib.rs` |
| libghostty を使わない理由 | `nebula-backend/src/terminal.rs` |

読み手向けの要約は README の「設計の要点」に 6 項目だけ置いた。

### 4. CI の門番と最低要求バージョン (`24e00cb`)

整形と lint を 3 プラットフォームすべてで門番にした。3 OS で回すのは冗長だからではなく、
`cfg(unix)` / `cfg(windows)` で実装が分かれており 1 OS だけでは片方の指摘を
取りこぼすため。`setup-rust` に `components: rustfmt, clippy` を明示した
(`dtolnay/rust-toolchain` は minimal profile なので、ランナーのプリインストールに
頼ると門番が静かに消える)。

`rust-version = "1.85"` は**偽だった**。`nebula-core` が let-chain を使っており、
これが安定化したのは 1.88。`cargo +1.85 check` は E0658 で落ち、`cargo +1.88 check` は通る。
値を実測に合わせ、CI が `Cargo.toml` から読んで検査するジョブを足した。

この訂正で clippy の `collapsible_if` が 3 箇所で新たに発火した。clippy は宣言された
MSRV より新しい構文を要する提案を伏せるため、1.85 と偽っている間は let-chain へ畳む
提案が出ていなかった。3 箇所とも畳んだ。

### 5. 握り潰している失敗の固定 (`f1b9588`)

影響の大きい fallback を characterization test で固定した (9 件追加)。
挙動は変えていない。削除と観測可能化 (ログ追加) は挙動変更にあたるため行っていない。

受容の理由と再検討の時期は `docs/issues.md` の表にまとめてある。
各テストには「この挙動が正しいと保証するものではない」と明記した。注記が無いと
握り潰しを正仕様として強化してしまう。

調べた結果、session の読み込み・保存の失敗、search の走査エラー、`create_file` の
存在確認、`git show` が HEAD に無いファイルで失敗する経路は既存テストで担保済みだった。

### 6. 巨大ファイルの分割 (`cfa4b35`〜`ba13ea2`)

1,500行超の 7 ファイルを worktree に分けて並行に分割し、レビューを通してから
1 本ずつ merge した。

| 元ファイル | 行数 | 分割後 |
|---|---:|---|
| `nebula/src/ui.rs` | 2,449 | 508 + `ui/text.rs` 425 + `ui/input.rs` 1,173 + `ui/input/element.rs` 404 |
| `views/terminal.rs` | 2,146 | 970 + `terminal/element.rs` 930 + `terminal/keys.rs` 299 |
| `views/editor_view.rs` | 2,120 | 1,149 + `completion.rs` 489 + `ime.rs` 250 + `mouse.rs` 127 + `edit_map.rs` 98 + `render.rs` 80 |
| `views/codex.rs` | 2,118 | 701 + `codex/chat.rs` 471 + `codex/format.rs` 274 + `codex/render.rs` 720 |
| `nebula/src/update.rs` | 1,718 | 365 + `update/version.rs` 181 + `update/release.rs` 457 + `update/install.rs` 781 |
| `views/git.rs` | 1,648 | 845 + `git/rows.rs` 400 + `git/actions.rs` 438 |
| `views/explorer.rs` | 1,560 | 1,104 + `explorer/tree.rs` 406 + `explorer/edit.rs` 78 |

#### ルートの `.rs` を必ず残した

`foo.rs` → `foo/mod.rs` のディレクトリモジュール化は**していない**。
`crates/nebula/src/ui.rs` の `WIRED_SOURCES` が
`include_str!("views/terminal.rs")` のように**ソースファイル相対**で
ほかのビューを読み込んでおり、`ui/mod.rs` へ移すと基準ディレクトリが変わって全滅し、
`views/terminal.rs` を `views/terminal/mod.rs` へ移すと参照先が消えるため。
`update.rs` の `include_str!("../../../.github/workflows/release.yml")` も同じ。

副次的に、この形なら**担当ファイルとその子モジュール以外を 1 行も編集しない**という
不変条件が本当に守れる。7 本の worktree が互いに衝突しない理由もこれ。

#### そのほかの不変条件

- `tooltip_text::` の呼び出しはルートに残す (`ui.rs` の配線検査テストは
  `WIRED_SOURCES` に列挙したルートファイルの本文しか走査しない)
- 子モジュールへ移した item は原則 `pub(super)`。`pub` は新規に増やさない。
  `Entity<_>` や `Subscription` を抱える共有状態型はルートに残す
- テストは検証対象と同じファイルへ移す。テストだけ別ファイルへ逃がす行数稼ぎは禁止
- 各 merge の直後に fmt / clippy / test を回す
